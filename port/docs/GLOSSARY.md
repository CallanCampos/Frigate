# Glossary

The words Frigate's code and documents use, from the DS's hardware, Nintendo's and Game Freak's libraries, the decomp
and Frigate itself. [ARCHITECTURE.md](ARCHITECTURE.md) shows how the parts fit.

## The project

| Term | Meaning |
| --- | --- |
| **Frigate** | The native PC port of Pokémon Black 2 and White 2 built from the pokebw2 decompilation, in `port/` of this repository; its programs are `frigate-black2` and `frigate-white2` |
| **The port, the layer** | Frigate's code, as opposed to the decomp's. Its internal names keep the word: the `port/` directory, the `port_` C prefix, the `PORT_*` CMake variables, the `port:` prefix of the program's messages |
| **The decomp, upstream** | pokebw2 (`fuddlesworth/pokebw2`), the decompilation this repository follows, merged through sync PRs that an Action proposes each hour and the owner reviews ([SYNC.md](SYNC.md)): everything outside `port/` is its, but for Frigate's game changes ([game-changes.md](game-changes.md)) and Frigate's own files under `.github/`: `README.md`, `CONTRIBUTING.md`, `CODEOWNERS`, the port's pull request and issue templates (`PULL_REQUEST_TEMPLATE/port.md`, `ISSUE_TEMPLATE/port_*.yml`) and the two `workflows/port-*.yml` |
| **ROM build, host build** | The ROM build (`configure.py` and `ninja`, with MWCC) rebuilds both ROMs from the decomp and checks their SHA1s; the host build (CMake in `port/`, with clang) makes Frigate. Both build from the same tree |
| **MWCC, matching** | Metrowerks CodeWarrior, the DS's C compiler. A matching function is C that MWCC compiles to the ROM's exact bytes; matching is upstream's work |
| **Complete, incomplete file** | A decomp file whose every function matches is marked complete in its `delinks.txt` and links into the ROM; an incomplete one still links the original code, so the ROM build proves nothing about its C. Frigate compiles both |
| **`PLATFORM_PC`** | Defined by the host build only (`port/CMakeLists.txt`). An `#ifdef PLATFORM_PC` block in a decomp file is one of Frigate's game changes ([game-changes.md](game-changes.md)) |
| **`uptr`, `sptr`** | An integer that holds an address: `u32` and `s32` for MWCC, so retyping a parameter or field changes no DS code, and as wide as a pointer on a host, where an address cut to 32 bits points nowhere (`include/types.h`, typedefs there so that the compiler's messages name them; [PLAN.md §4.8](PLAN.md#48-64-bit-and-dual-target-rules)). The game's Neutral changes ([game-changes.md](game-changes.md)) |
| **Pointer cast guard** | The test `game_ptrcasts`: the game's C compiled again with the cast warnings on, each cast that would cut an address to 32 bits on a host held to a baseline of known ones, each classed real, harmless, handled or unreachable ([ADR 0019](adr/0019-pointer-cast-guard-against-a-classified-baseline.md), [SYNC.md](SYNC.md#when-the-pointer-cast-guard-fails), [../tools/check_ptrcasts.py](../tools/check_ptrcasts.py)). Its `--report` line is T1's 64-bit measurement |
| **`BUGFIX`** | The decomp's switch for its `// BUG:` fixes. Off in Frigate, so the game plays as the original; memory-safety bugs are fixed under `PLATFORM_PC` instead |
| **swan** | The community's names for BW2's symbols, which the decomp uses first |
| **GBATEK** | The DS's hardware reference, which the renderers and the platform layer cite for each fact |
| **ADR** | An architecture decision record, in [adr/](adr/README.md) |
| **T0 to T7** | The test levels: the ROM build's SHA1s, the host build, unit tests, replays, the oracle, sanitizers, saves and ROM checks, playtests ([../CLAUDE.md](../CLAUDE.md#testing-planmd-6)) |
| **Ruleset** | GitHub's rules for `main`, two of them, kept as `port/tools/main-ruleset.json` and `port/tools/reviews-ruleset.json`: one with no bypass for anyone (every change through a pull request, no force-push or deletion, the branch up to date, conversations resolved, merge commits only, four required checks), and one for review (an approval and the code owner's review, which a new push dismisses) ([REPOSITORY-POLICY.md](REPOSITORY-POLICY.md), [ADR 0018](adr/0018-protected-main-and-sync-prs.md)) |
| **Frigate local verification** | The required check that CI can't give, because it needs the player's two ROMs: a maintainer runs `port/tools/sync_upstream.sh --verify-pr N` on a pull request's exact head, in a clean worktree prepared with `bootstrap_checkout.sh`, and it builds both ROMs and checks their SHA1s, builds and tests the host in both versions, and posts the status as the account gh is signed in with. Only a status that CallanCampos (user ID `145432210`) created counts ([REPOSITORY-POLICY.md](REPOSITORY-POLICY.md)), so it runs where gh is signed in as the owner. A new push needs a new run. It doesn't build the melonDS oracle, so T4 isn't part of it ([SYNC.md](SYNC.md#validate-and-approve-a-proposed-pr)) |
| **Sync PR, sync App** | A pull request that merges upstream into Frigate: a real merge with its `Upstream-Commit` trailer, on a `codex/upstream-sync-*` branch, carrying only the merge's own resolutions. The hourly `port-sync` Action proposes one at a time as the sync App, *Frigate Upstream Sync*, a GitHub App installed on Frigate alone that may push that branch and open the PR, never approve or merge it; a maintainer can prepare one with `sync_upstream.sh`. Either waits for local verification and the owner's approval ([SYNC.md](SYNC.md)) |
| **Owner review exception** | The one bypass in the rulesets: the owner, Frigate's only maintainer, may merge a pull request they wrote without a second person's approval, since GitHub doesn't let an author approve their own. It lifts only the review rule, never the pull request, the checks, resolved conversations or the history rules, and it is not for sync PRs or contributors' pull requests, which get the owner's explicit approval ([REPOSITORY-POLICY.md](REPOSITORY-POLICY.md)) |

## The DS

| Term | Meaning |
| --- | --- |
| **ARM9** | The DS's main processor (an ARM946E-S), which runs the game. Everything in `src/` and `lib/` is ARM9 code; Frigate compiles it for the host |
| **ARM7** | The DS's second processor, which runs Nintendo's own code for sound, touch, the clock, power, the firmware and wireless. The decomp doesn't have it; Frigate replaces it with host services behind PXI ([../hal](../hal/README.md)) |
| **PXI** | The FIFO between the two processors: 32-bit words, each with a tag for its service. The platform layer delivers each word to the host service of its tag at once |
| **ITCM, DTCM** | The ARM9's tightly coupled memories: ITCM, 32 KiB of fast code (the interrupt handler, hot renderers), and DTCM, 16 KiB of fast data (the interrupt table, stacks, a small heap), at 0x02fe0000 in BW2. On the host DTCM is a 16 KiB block ([../hal/os/memory_map.c](../hal/os/memory_map.c)) |
| **Main memory, arena** | The DS's 4 MiB of RAM; the SDK divides what the program leaves free into arenas, from which the game carves its heaps. Frigate's main arena is 16 MiB of host memory |
| **Overlay** | A block of ARM9 code and data loaded on demand into a region it shares with others (344 in each version). The decomp's `src/ovNNN/` holds overlay NNN's files. Frigate links all of them into the program, and loading one sets its writable statics back as the DS does ([../hal/fs/ovsec.h](../hal/fs/ovsec.h)) |
| **2D engines A and B** | The main (A) and sub (B) 2D graphics engines, one for each screen; POWCNT1 decides which feeds the top screen and which the bottom, and engine A can show the 3D picture as its background 0 |
| **BG** | A background layer: four per engine, each text (tiled), affine, extended or bitmap |
| **OAM, OBJ** | Object attribute memory: 128 sprite entries per engine. OBJ is the hardware's word for a sprite |
| **VRAM banks, VRAMCNT, LCDC** | Nine banks of video memory, A to I, that VRAMCNT maps into backgrounds, sprites, textures, palettes, or LCDC, where the CPU reads and writes them directly (0x06800000). [../hal/gx/vram.c](../hal/gx/vram.c) maps them by page aliasing |
| **DISPCNT, POWCNT1** | The display control register of each engine (mode, layers shown), and the power control register (which engine feeds which screen) |
| **VBlank, HBlank, VCOUNT, DISPSTAT** | The vertical blank (lines 192 to 262), when the game swaps buffers and uploads to VRAM; the horizontal blank after each line's 256 dots; the line being drawn. Frigate's virtual clock drives all three. DISPSTAT holds the flags the ARM9 reads of them: its HBlank flag sets 1606 cycles into each line, and Frigate takes the HBlank interrupt at the same moment, as melonDS does, so that a handler sees the flag. The screen wipes that cover or uncover the screens line by line write their windows from an HBlank handler only while the flag is set (`src/system/wipe_sub.c`) |
| **Geometry engine, GXFIFO** | The DS's 3D command processor, fed through command ports and the GXFIFO; it transforms, lights and clips polygons for the rendering engine. [../gfx/ge](../gfx/README.md) models it |
| **Display capture** | Hardware that writes a composed picture into a VRAM bank, used for motion blur and 3D on both screens ([../gfx/capture.c](../gfx/capture.c)) |
| **Backup, flash** | The cartridge's save chip, a 4 Mbit (512 KiB) flash in BW2. Frigate keeps it as `IREO.sav` (Black 2) or `IRDO.sav` (White 2), named after the ROM's game code |
| **NitroFS, FAT, FNT** | The cartridge's file system, with its allocation and name tables; every file the game reads is in it |
| **NARC** | Nitro archive: one NitroFS file that holds many numbered members, read by `src/gfl/arc_tool.c` |
| **SDAT, SSEQ, SBNK, SWAR, STRM** | The sound archive and what it holds: sequences, instrument banks, wave archives, streams |
| **G2D files: NCGR, NCLR, NCER, NMCR, NANR, NFTR** | NitroSystem's 2D graphics files: characters (tiles), palettes, cells, multi-cells, animations, fonts. The DS relocates them in place; Frigate rebuilds them as host structs ([ADR 0007](adr/0007-nitrosystem-files-in-host-structs.md)) |
| **Infrared chip, card SPI bus** | BW2's cartridges carry an infrared chip on the card slot's SPI bus, which also reaches the save's flash; the ARM9 drives the bus through `AUXSPICNT` and `AUXSPIDATA`. Frigate models both as melonDS has them ([../hal/card/card_spi.c](../hal/card/card_spi.c), [ADR 0011](adr/0011-cartridge-infrared-chip-as-a-register-model.md)) |
| **DSi, TWL** | The DSi and its SDK's code name. BW2 runs on both; Frigate is a DS, so every DSi path is skipped |

## Nintendo's and Game Freak's libraries

| Term | Meaning |
| --- | --- |
| **NitroSDK, TwlSDK** | Nintendo's DS and DSi SDKs (`lib/nitro`, `lib/twl`): OS, GX, FS, CARD, SND, PXI, MI, FX and the rest |
| **NitroSystem, NNS** | Nintendo's middleware above the SDK (`lib/nnsys`): FND heaps, G2D, G3D, GFD VRAM transfers, the sound players |
| **SPL** | Nintendo's particle library (`lib/spl`) |
| **DWC** | Nintendo Wi-Fi Connection (`lib/dwc`), the online library |
| **DS Protect** | Nintendo's anti-piracy library (`lib/dsprot`); Frigate's stub passes its checks as on a genuine cartridge |
| **MSL** | The Metrowerks Standard Library (`lib/msl`), MWCC's C library and runtime, which the ROM links. The host's C library replaces it, but for the runtime routine that the game's C calls by name, the division `_u32_div_f` ([../hal/msl](../hal/msl/fp_fastI.c)), and MSL's string extensions (`hal/stubs`) |
| **GFL** | Game Freak's library (`src/gfl`): heaps, overlays, archives, processes, tasks, backgrounds, cell actors, input, text |
| **Process (proc)** | A GFL process: a screen or mode with its init, main and exit functions and its overlay (`src/gfl/procsys.c`) |
| **TCB** | A GFL task (task control block) in a priority list run each frame, each VBlank or each HBlank (`src/gfl/tcb.c`) |
| **Cell actor (ClAct)** | GFL's sprite system (`src/gfl/clact.c`), which draws NitroSystem cells and animations through OAM |
| **Field menu, app call** | The menu X opens in the field (overlay 36's `field_menu.c`): POKéMON, POKéDEX, BAG, the trainer card, SAVE and OPTIONS, fewer without a Pokémon or the Pokédex. Each item opens an app, a process of its own overlay, through overlay 12's app call (`EventFieldAppCall`, `src/ov012/event_field_proclink.c`), which closes the field, runs the app and opens the next one it asks for or the field again |
| **Game event, event type** | A game event (`GameEvent`, `src/system/game_event.c`) is a step of the game's flow with a state machine of its own, run each pass of the main loop until it ends; it can chain a child event that runs in its place until that one ends (`GameEvent_ChainNext`). CONTINUE's event chains `EventFieldOpen` to open the field. An event type is what an app's result asks of the field menu once the app call closes the app (`EventFieldAppCall_ConvAppResultToEventType`): 0 shows the menu again, 1 closes it, and 2 (a field move), 3 (a field event, such as an item's use) and 5 (a script) act in the field |
| **Genuine-card check** | The game's check of the cartridge's infrared chip (`src/ov338/ir_check.c`), at every CONTINUE and NEW GAME and when a Pokémon faints in battle: a chip that doesn't answer its ID hides the C-Gear's new-beacon marks for good and stops battles giving experience. Frigate's model of the chip passes it |
| **MCSS** | The system that draws Pokémon and trainer sprites from multi-cell animations, in 3D, for battles and other screens (`src/system/mcss.c`) |

## Frigate's own terms

| Term | Meaning |
| --- | --- |
| **Platform layer, HAL** | [port/hal](../hal/README.md): host C for the parts of the SDK and the ARM7 a host doesn't have |
| **SDK surface** | What the game's C reaches that the platform layer takes over: the SDK's assembly, its hardware-bound files, the DS's addresses and registers, the ARM7 |
| **Virtual clock** | Frigate's count of the ARM9 bus's cycles (33.514 MHz), which moves only through halts, modelled busy waits and `OS_GetTick`, so that runs are deterministic ([../hal/os/core.c](../hal/os/core.c)) |
| **Dispatcher, fiber** | The loop on the host thread's own stack that resumes the SDK's threads, each a fiber (a stack and saved registers), and runs interrupts and host work between them |
| **Frame hook, scanline hook** | Host functions run at each VBlank, and at the start of each visible line, on the dispatcher's stack ([../hal/os/port_os.h](../hal/os/port_os.h)) |
| **Timed work** | Host work that a module sets for a cycle of the virtual clock (`port_os_set_timed_work`) and the OS core runs on the dispatcher's stack when the clock reaches it: the sound driver's next alarm ([../hal/os/port_os.h](../hal/os/port_os.h)) |
| **Trap stub, data placeholder** | A generated stand-in for a DS function or data object that has no C yet: reaching it stops the program with its name and status 70 ([../hal/trap.c](../hal/trap.c), [../tools/gen_stubs.py](../tools/gen_stubs.py)) |
| **Host seam** | [port/hal/host](../hal/host/host.h): the operating system's services that the platform layer, the program and the tests share where macOS, Linux and Windows differ (pages, faults, backtraces, names, the watchdog, the clock, threads, files), one file a host; a module whose own feature is a host's (the saves' folder, the VRAM's aliasing, the mapped ROM) keeps its branches, which [hal/README.md](../hal/README.md#names) lists ([ADR 0013](adr/0013-windows-build-with-msys2-clang64.md)) |
| **MSYS2, CLANG64** | The Windows distribution of Unix-style tools and its environment of clang, lld and compiler-rt over Microsoft's Universal C Runtime (UCRT), with CMake, Ninja, Python and SDL3, which Windows builds Frigate with, in CI too ([ADR 0013](adr/0013-windows-build-with-msys2-clang64.md)) |
| **`replaced.txt`, `*_host.c`, `port_sdk_*`** | The three ways the platform layer takes over a decomp file: leaving it out, compiling it through a host file, or renaming its functions ([../hal/README.md](../hal/README.md#how-a-decomp-file-is-adapted)) |
| **`PORT_HW_ADDR`, hwinclude** | The build's translation of the SDK headers' DS addresses into host memory windows ([ADR 0004](adr/0004-ds-addresses-by-header-translation.md)) |
| **Plain C types only** | What a header of the platform layer says when it includes none of the decomp's headers, so that `port/app`, `port/gfx` and `port/audio`, which never include them, can include it |
| **Oracle** | melonDS running the player's ROM headless (`pbw-oracle`, [../tools/oracle](../tools/oracle/README.md)): the reference Frigate is compared with, a test tool only. The asm oracle ([../tests/asm_oracle](../tests/asm_oracle/README.md)) is the same idea for single functions, with Unicorn |
| **pbwinput, run directory** | The input file format that the oracle and Frigate's replays share, and the directory a run writes for comparison (`frames.tsv`, screens, memory dumps) |
| **Periodic run, play** | A run of the ARM7 sound driver's thread is periodic when its alarm wakes it, every 2728 ticks of 64 cycles (about 192 a second), the only runs that move the sequences on; a play is a player's sequence from its start to its stop. The sound comparison pairs the two programs' plays, and their runs by the count of periodic runs since the play's start ([../tools/oracle/README.md](../tools/oracle/README.md#sound)) |
| **Sound trace** | The ARM7 sound driver's state after each run of its thread, in the DS's layout (`pbwsnd 1`, [../tools/oracle/sndtrace.h](../tools/oracle/sndtrace.h)), which the oracle and Frigate write with `--sound-trace` for `sound.py` to compare |
| **Game frame, video frame** | A pass of the game's main loop (GFL's frame count) and a VBlank. The field runs at 30 passes a second, so the two differ |
| **Replay** | A run of the program driven by an input file (`--input`) instead of the player |
| **Pinned clock** | An input file's `clock pinned`: the real-time clock stays at the file's time for the whole run, on the oracle and on Frigate alike, where it would otherwise run on with each program's video frames, which the DS takes more of to reach the same count; so a screen that shows the clock (the field menu's) shows the same time on both ([../tools/oracle/README.md](../tools/oracle/README.md#input-files)) |
| **Random seed, given seed** | The seed `buildSeed` builds from the console's entropy for GFL's random numbers at start-up and for each battle's at its start (`src/gfl/gf_standard.c`). The DS's comes from its CPU's timing and its stack, which no host has; an input file's `seed` lines give the DS's to Frigate, which takes them in their order in place of its own ([../hal/gfl/random_seed.h](../hal/gfl/random_seed.h)), and `oracle.py seeds` reads them from the oracle's memory ([../tools/oracle/README.md](../tools/oracle/README.md#random-seeds)) |
| **Random state** | GFL's random generators where a sequence compares them with the DS's: the linear generator's state (`gfl_use.c`'s work) and the Mersenne Twister's first word and index (`gf_standard.c`'s tables), dumped by both programs at each frame (`RANDOM_STATE` in [../tools/oracle/oracle.py](../tools/oracle/oracle.py), [../hal/gfl/random_state.h](../hal/gfl/random_state.h)). Equal at a count, the game has drawn as many numbers by then as the DS |
| **Bands, workers** | The 3D renderer draws its frame in bands of lines at once, blocks of 8 lines dealt round the parts, each drawing every polygon on its own lines; part 0 is the game's thread and the others are the renderer's workers, threads that run nothing else (`--render-threads`, [../gfx/workers.h](../gfx/workers.h), [ADR 0016](adr/0016-3d-frame-in-bands-on-worker-threads.md)). The picture is the same however many draw it |
| **Frame times, busy time** | How long the program takes on the host to make each of the DS's frames, the 16.715 ms it has at 59.8261 a second: `--frame-times` writes them a row a frame, the whole frame, its busy time (the frame without the pacing wait: the work done for it) and its parts ([../hal/os/frame_time.h](../hal/os/frame_time.h)); [../tools/frame_times.py](../tools/frame_times.py) reports a scene's median, 95th percentile and most, each frame the least of several runs, and the `frame_times_*` tests hold them to a budget |
| **Route** | A test whose program runs the game from power-on on the player's ROM: a replay, an oracle sequence or the port's check of its hashes, the smoke test. ctest's label `route` picks them ([../tests/README.md](../tests/README.md)) |
| **Sanitized build** | The host build with `-DPORT_SANITIZE=ON`: the game and every test under AddressSanitizer and UndefinedBehaviorSanitizer, every report fatal, T5's build ([sanitizers.md](sanitizers.md)) |
| **Poisoned memory** | Memory that AddressSanitizer reports any access to. In the sanitized build, the game's heap memory outside its allocated blocks is poisoned, so an overrun from one of the game's allocations into the next is a `use-after-poison` report |
| **DS read past a block** | A read the game makes past the end of one of its heap blocks, into what the heap holds after it, whose bytes it then uses as the DS does (the copyright screen's characters, which the title screen shows). Frigate keeps the read, and the sanitized build lets that one read through instead of reporting it (`port_heap_ds_read_begin`, [sanitizers.md](sanitizers.md)), as long as it stays in the game's heaps or the main arena |
| **Frame held close** | A port frame of an oracle sequence whose screens with 3D must also have few pixels that differ at all from the oracle's (`compare.py --close`, a sequence's `close`), where a 2D layer that differs by a step everywhere, as in a fade, would pass the 3D's tolerance ([../tools/oracle/README.md](../tools/oracle/README.md#comparing)) |
| **Known difference** | A frame that an oracle sequence leaves out of its comparison, or only its top screen (`known_top`), an oracle frame that no port frame can show, or a stretch where it pairs the frames a pass apart (a lag), because the two programs can't agree there by construction: the DS's CPU takes time and drops frames, and its random numbers are seeded otherwise. Each is declared with why in `oracle.py`'s `SEQUENCES`, with its evidence in [../tools/oracle/README.md](../tools/oracle/README.md#known-differences-from-the-hardware); a difference whose cause isn't traced is a failure, never a known difference, and any other difference fails |
| **Exit route** | Phase 3's exit test ([PLAN.md §7](PLAN.md#phase-3-new-game-to-the-overworld-m3-m4)): the oracle sequence `aspertia`, a new game from a blank save through the intro into Aspertia City, a walk, a talk with a townsperson, a house entered and left and four changes of map, every frame held to melonDS in both versions (ctest `oracle_aspertia`), and without the oracle its counts, its screens without 3D and NNS G3D's state, the camera that follows the player, at the frames its reference keeps (`oracle_aspertia_hashes`) |
| **Ignorelist** | The file that tells clang which checks to leave out of which functions ([../cmake/sanitizer_ignorelist.txt](../cmake/sanitizer_ignorelist.txt)); in Frigate, only code that is right on every host |
| **Test launcher** | Frigate's former `--launch` ([ADR 0012](adr/0012-test-launcher-for-the-field-menus-apps.md)), which records still name: while the field had no C, it opened the field menu's apps in the field's place when a continued game asked for the field, so that the tests could hold them to the oracle's route through the field menu. Retired on 2026-10-24, once the field opened; its routes are the oracle's `field_menus` and `party_menus` sequences, through the field menu itself |
| **Saves made on the oracle** | Saves that melonDS makes by playing an input file (`oracle.py save`, `SAVES`), the first from a blank save and each later one from the save before it, each checked against the SHA-1 `oracle.py` keeps. The tests start from the first save, the starter save (a Pokémon and the Pokédex) and phase 4's route saves (`center_save` in the Pokémon Center after Hugh's battle, `route19_save` beside Route 19's grass, `catch_save` after the first catch), which ctest's `oracle_saves` makes into the build tree, where later runs reuse them |
| **Round trip, cut** | A round trip (`oracle.py round-trip`, `ROUND_TRIPS`) has Frigate make a save that melonDS makes too, from the same start save, and holds the two byte by byte, every byte that differs declared with its cause; melonDS then continues both, and Frigate its own. A cut is where an oracle route parts from melonDS by construction, where the DS's CPU time decides the game's course, such as a trainer's AI ([ADR 0023](adr/0023-oracle-routes-part-where-the-ds-cpu-time-decides.md)): a sequence ends before it, and a round trip with a cut holds Frigate's run frame by frame up to it and by the save past it, with presses of Frigate's own where its course takes other passes (`hugh`) |
| **Game change** | A change Frigate makes outside `port/`, of one of three allowed kinds, each in [game-changes.md](game-changes.md) |
| **Universal program, slice** | A macOS program with code for more than one processor, each a slice: the distribution build's has an arm64 slice for Apple Silicon and an x86_64 slice for Intel Macs, and macOS runs the one for its processor. `lipo -archs` lists them; `otool` reads one, so the tools read every slice (`-arch all`) |
| **Rosetta** | Apple's translator that runs an x86_64 program on Apple Silicon; here it runs the universal program's x86_64 slice for its tests (`arch -x86_64`). Apple keeps it whole through macOS 27 |
| **Deployment target, minos** | The oldest macOS a build is for (`CMAKE_OSX_DEPLOYMENT_TARGET`, `-mmacosx-version-min`), which the linker writes as each slice's `minos` in its `LC_BUILD_VERSION` load command and the app as `LSMinimumSystemVersion`. A development build sets none and gets the SDK's |
| **Distribution build** | The macOS build for other Macs than the one that builds it (`PORT_MACOS_DISTRIBUTION`, `build/port-dist`, [ADR 0015](adr/0015-universal-macos-app-for-macos-11.md)): a universal program built for macOS 11 and later (tested so far on macOS 15 and 26), with SDL3's pinned release linked in. It changes nothing about uploading: none is done |
| **Ad-hoc signature, Gatekeeper, Open Anyway** | The app is signed with no identity (`codesign --sign -`), which Apple Silicon needs to run it, and not notarized ([ADR 0003](adr/0003-ad-hoc-signing-no-apple-developer-account.md)); Gatekeeper, macOS's check of apps from elsewhere, blocks such an app until the player allows it once in System Settings' Privacy & Security (Open Anyway), as [../README.md](../README.md#the-macos-app) says |
