# Frigate review — 2026-10-21

Frigate compiles the decomp's C as native host code, with the player's ROM supplying data. The latest sync to
`fc478a9ee5` includes the field engine, so the older statement that overlay 36 has no C no longer describes the build.
This is a focused engineering review and validation snapshot, not an exhaustive audit.

## Architecture and scope

The [architecture map](ARCHITECTURE.md) describes the SDK HAL, host fibers and virtual clock, overlay static reset,
software renderer and ARM7 services. These are concrete native subsystems: the HAL models the SDK-facing hardware and
services, and the host runs game C rather than executing ARM instructions. The ROM remains a checked data source;
melonDS remains a separate test oracle. Fibers and virtual time preserve the game's scheduling assumptions, and static
reset gives linked overlays their load-time state. The renderer and ARM7 sound/service models have their own unit and
differential tests; their existence does not establish equivalence for every gameplay path.

The mod platform is planned. Current work changes C and rebuilds; layered assets, Lua and general mod hooks are not an
implemented public mod API. [MODDING.md](MODDING.md) distinguishes those plans from today's workflow.

## What the checks establish

Both host versions build and both DS ROM SHA1s match. The initial merge's global MWCC comparison has 3,550 of 3,554
identical token streams; its existing TrainerCardParam and VM exceptions belong to complete files and are covered by
T0. Against the latest sync, targeted SDK token streams are identical in 20/24 file/version pairs. The four
exceptions are `friend.c` and `dwcutil_ac.c` in both versions; exact object proof covers all ten DWC file/version
pairs (754 function instances), allocated sections and exact relocation targets. DWC utility uses the configured
`2.0/sp2` compiler. Evidence is `/tmp/frigate-latest-neutral.log` and
`/tmp/frigate-dwc-proof-fc478/{results,relocation-proof}.json`. Hashes protect the ROM build; incomplete C may still
link original objects there, so they cannot establish its host semantics.

Fresh non-timing CTest suites pass after the latest sync: Black 2 has 281 pass and 16 skip of 297 (173.83 s),
White 2 has 279 pass and 16 skip of 295 (166.14 s).
The registered assembly oracle uses `SVC_UnpackBits` and the correct version in each build. Both suites skip 15 optional
oracle tests without their binary and the universal app slice check. T5 sanitizers and T7 scripted visual playtests
were not run this pass; optional T4 full oracle coverage was skipped. See [STATUS.md](STATUS.md) for exact scope and
evidence logs.

The comparable native pointer/int measurement explicitly enables all four cast families in configured commands.
Against `a14364b6ba`, game instances fall 245 to 234 and library instances 247 to 235, despite 117 additional native
translation units. All 3,193 baseline/current syntax checks pass. Separately, optional integer-shortening diagnostics
rise 277 to 388; that is further numeric-width work, not evidence of a pointer-clean port. The host build has 31
function traps and 22 data placeholders per version. The source scanner detects a definition for every non-veneer
code symbol, but includes 224 SDK assembly definitions and 3,868 functions in partial files: source coverage alone
does not establish native readiness.

The fixes preserve real pointer round trips, opaque callback contexts and callback types. MSL comparison extensions
use private names to avoid the Windows libc ABI; GameStats, ND and SSL use native string declarations on hosts.
All 16 affected file/version pairs preprocess identically to upstream (`/tmp/frigate-winfix-all-neutral.log`), and
the refreshed warning probe is `/tmp/frigate-winfix-warning-full/{summary,results}.json`. WCM's native DS workspace
grows from 8,960 to 9,024 bytes; its AP header also requires native pointer alignment. One shared adapter supplies the
extent to the SDK and both DWC wrappers. The regression rejects short/negative lengths, preserves complete addresses
and checks canaries around the workspace and AP buffer; restoring the old DS minimum makes it fail. DSi NDMA, WRAM,
NWM and secure-card DMA still have deferred hardware/transport boundaries; residual warning counts do not certify
those paths. Wireless multiplayer remains a later milestone.

## The current field blocker

The 10,600-frame New Game replay passes. The extended trace stops at frame 10,759 in `FieldmapProc_Init`, through
`OS_Terminate`, after `HEAPID_FIELD_PLACE_NAME`. The external `g_FieldHeapMemory` buffer is 64 KiB, while the host
policy doubles weather's `0x6400` and place-name's `0x7400` allocations to a combined `0x1b000`, already beyond that
buffer before overhead. This is the immediate heap-capacity issue to resolve and retest, not proof that the rest of
field entry works.

The test launcher detects the real `FIELDMAP_PROC_FUNCS` and steps aside automatically. Earlier bag, trainer-card,
party and Pokédex oracle comparisons remain evidence for their recorded revisions; they do not provide current
field/app coverage. After the heap correction, repeat extended entry, CONTINUE, real menu paths and differential
checks before claiming a playable overworld.

## Collaboration and next work

[CONTRIBUTING.md](../CONTRIBUTING.md) and [ADR 0017](adr/0017-external-contributions.md) now give outside contributors
personal forks, topic branches and PRs to Frigate's `main`. Maintainers retain sync and both-ROM verification duties;
external reference sources and the independent-upstream boundary are documented there. This makes small fixes
reviewable without imposing the maintainer's direct-publish loop on contributors.

The seven preserved uncommitted wt-64 files and `build/wt-64` were left intact. The older local Claude memory's
October 17 phase-0 description trails the October 19 status record; repository living documents should guide current
work. Priority is field heap sizing, meaningful field coverage, comparable warning measurements, then the planned mod
interface and further gameplay paths as their C permits.
