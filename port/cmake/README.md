# port/cmake/

The host build's fragments. [../CMakeLists.txt](../CMakeLists.txt) sets up what everything shares (the version, the
generated tree, SDL3, the decomp's language model, the four object libraries `pokebw2_game`, `port_hal`, `port_gfx` and
`port_app`, the trap stubs and the program) and then includes every `*.cmake` here in name order. Each fragment holds
one module's build rules (its per-file options, its generated inputs) and the tests of that module, so that a module's
build and tests are read in one place.

## Options

Each is given at configure time, `cmake -S port -B build/port -DNAME=VALUE`.

| Option | Default | Where | What it does |
| --- | --- | --- | --- |
| `PORT_VERSION` | `b2_us` | [../CMakeLists.txt](../CMakeLists.txt) | The game: `b2_us` (Black 2, `frigate-black2`) or `w2_us` (White 2, `frigate-white2`). One build directory per version |
| `PORT_ROM_LANGUAGE` | `us` | [../CMakeLists.txt](../CMakeLists.txt), [rom.cmake](rom.cmake) | The ROM's language: `us`, the decomp's dump, or `es`, an experimental Spanish Black 2 dump (`IRES`, only with `b2_us`) whose files the US code reads, by the entry [rom_manifest.py](../tools/research/assets/rom_manifest.py) writes from it into `nitrofs_manifest_languages.json` ([ADR 0025](../docs/adr/0025-a-spanish-rom-by-a-manifest-of-its-own.md)). One build directory per language |
| `PORT_FETCH_SDL3` | `ON` | [../CMakeLists.txt](../CMakeLists.txt) | Builds SDL3's pinned release when no installed SDL3 3.4 is found |
| `PORT_MACOS_DISTRIBUTION` | `OFF` | [../CMakeLists.txt](../CMakeLists.txt) | macOS: the build for other Macs ([ADR 0015](../docs/adr/0015-universal-macos-app-for-macos-11.md)), in a build directory of its own: `CMAKE_OSX_ARCHITECTURES` `arm64;x86_64` and `CMAKE_OSX_DEPLOYMENT_TARGET` `11.0` unless given, and SDL3's pinned release, always, linked statically. `../tools/package_macos.sh --distribution` configures it, builds it and makes the disk image. Then the directory stays the distribution build's: configuring it without the option stops. With a deployment target, every target the port defines and SDL3 fail on a call to a newer macOS API (`-Werror=unguarded-availability`) |
| `CMAKE_OSX_DEPLOYMENT_TARGET`, `CMAKE_OSX_ARCHITECTURES` | empty: this Mac's | CMake | The macOS and the processors the build is for. With a deployment target, a call to an API newer than it fails the build (`-Werror=unguarded-availability`), and the app is refused if any of its binaries is built for a newer macOS or lacks a slice |
| `PORT_SANITIZE` | `OFF` | [../CMakeLists.txt](../CMakeLists.txt) | The sanitized build: every target of this project but SDL3 under AddressSanitizer and UndefinedBehaviorSanitizer, every report fatal (the program aborts, and a report in a test's output fails it, which no test's `WILL_FAIL` may invert: configuring stops on one), with [sanitizer_ignorelist.txt](sanitizer_ignorelist.txt)'s checks left out, the game's heaps poisoned ([nnsys.cmake](nnsys.cmake)) and the OS tests run again on fake stacks ([os.cmake](os.cmake)); clang only. The oracle, a project of its own, stays as `PORT_ORACLE_SANITIZE` builds it; the modules' `*_sanitized` test variants keep their own flags, and their `*_plain` twins are sanitized too; the timing gates are refused with it; its macOS app links the toolchain's ASan runtime, for testing only; with `PORT_MACOS_DISTRIBUTION` both slices are sanitized, and `../tools/ctest_one_slice.sh` runs the x86_64 one's tests under Rosetta. [../docs/sanitizers.md](../docs/sanitizers.md) |
| `PORT_SANITIZE_RECOVER` | `OFF` | [../CMakeLists.txt](../CMakeLists.txt) | With `PORT_SANITIZE` (refused without it), a run goes on after a report, so that one run lists every report of a route; the `*_sanitized` test variants stay fatal |
| `PORT_MACOS_APP` | `OFF` | [macos_app.cmake](macos_app.cmake) | Makes the macOS app with every build, not only with its target |
| `PORT_MACOS_BUNDLE_ID_PREFIX` | `io.github.callancampos.frigate` | [../app/macos/bundle_id.cmake](../app/macos/bundle_id.cmake) | The app's bundle identifier before `.black2` or `.white2`; a build that isn't Frigate's gives its own. A build directory's old placeholder, `com.example.pokebw2-native`, is moved to the default |
| `PORT_BUILD_ORACLE` | `OFF` | [oracle.cmake](oracle.cmake) | Fetches melonDS and builds the test oracle, `pbw-oracle` |
| `PORT_ORACLE_SANITIZE` | `OFF` | [oracle.cmake](oracle.cmake) | Builds the oracle's own sources with AddressSanitizer and UndefinedBehaviorSanitizer |
| `PORT_OVSEC_LAYOUT` | `split` | [overlay_sections.cmake](overlay_sections.cmake) | `split` (data and bss sections apart) or `combined` (one section per overlay) |
| `PORT_OVSEC_BUDGET` | `150` | [overlay_sections.cmake](overlay_sections.cmake) | The most overlay sections a Mach-O link may have before the check stops it |
| `PORT_TEST_BOOT_LOGOS` | `OFF` | [integrate.cmake](integrate.cmake) | Adds `integrate_boot_logos`, 120 frames to the first logo screen |
| `PORT_FRAME_TIME_BUDGET_MS`, `PORT_FRAME_TIME_REPORT_ONLY` | `8.36`, `OFF` | [frame_times.cmake](frame_times.cmake) | The most a `frame_times_*` route's scene may take at its 95th percentile, each frame's least over 3 runs without the pacing wait, in ms (half the DS's frame); and whether those tests only report their scenes, for a machine too slow or too loaded for the budget |
| `PORT_GFX_TIMING_GATE`, `PORT_GFX_TIMING_LIMIT_US` | `OFF`, `2000` | [gfx_tests.cmake](gfx_tests.cmake) | Runs the 2D renderer's timing as a test, with its limit in microseconds |
| `PORT_G3D_TIMING_GATE`, `PORT_G3D_TIMING_LIMIT_US` | `OFF`, `5000` | [g3d.cmake](g3d.cmake) | The same for the 3D renderer |

The sanitized build is a build directory of its own (`-DPORT_SANITIZE=ON`, in `build/port-san`);
[sanitizer_ignorelist.txt](sanitizer_ignorelist.txt) lists, for clang, the checks it leaves out of the game's code, each
with the reason it is safe on a host. The tests carry labels by what they need, which each fragment gives its tests
where it defines them, with `port_test_labels(TEST LABEL...)` ([../CMakeLists.txt](../CMakeLists.txt)): `route` (the
program runs the game from power-on on the player's ROM), `oracle` (the melonDS oracle or its saves), `timing` (a
limit on the host's time: the `frame_times_*` routes and the timing gates) and `static` (the game's C read, not run:
[game.cmake](game.cmake)'s pointer cast guard and [progress.cmake](progress.cmake)'s measure), so that
`ctest -L route -LE oracle` runs the routes that need no oracle ([../tests/README.md](../tests/README.md)). A new
fragment's test that runs the game from
power-on gets `route` there, and `oracle` too when it needs the oracle.

## Adding a fragment

A new module's fragment is `<module>.cmake`, opening with a comment that says which module it builds and which part of
the game that serves. Its tests take the module's name as their prefix, set a `TIMEOUT`, give every run of the program
a `--save-dir` in the build tree, and skip with status 77 (or the program's 66, no ROM) when they need something the
machine doesn't have, so that CI, which has no ROM, still passes.
