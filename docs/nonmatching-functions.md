# Nonmatching functions

Every function that is in C but doesn't compile to the original. The addresses are Black 2's and White 2's.
`tools/decomp/compiler_probe.py FILE --version b2_us` (and `w2_us`) shows the difference of each function in a file,
and `--show-diff 1.1p1` the instructions.

## In C, not matching

These functions are written as the closest natural C found. Unless a row says the full ROM matches, their files are
partial (no `complete` in `delinks.txt`), so the original code is linked until they match. The differences are the same
in both versions.

## Matching, but not linkable as is


- `src/ov207/p_sta_sub.c`'s functions all match, but its `.rodata` can't be completed yet. It starts with 8 bytes at `0x021bafc0` / `0x021bb000` (`7f 00 00 18 00 90 01 00`) that nothing references. They are not one object: they read as a `u8` 127, a `u16` 0x1800 and an `fx32` 25.0, which are the constants the code uses folded (`iconSetup.y = 127` in `PStaSub_CreateActors`, `* 0x1800 / 10` in `PStaSub_AnimCircle`, `FX32_CONST(25) * sub->turnTimer` in `PStaSub_Main`), packed by size with the two 8-byte icon tables after them, so all five sit in the file's shared section (the link aligns every section to 4, so three sections of their own would take 12 bytes). How the three stay referred to while their reads fold is open: as `static const` scalars they are dropped (the functions still match), as non-`static` `const` globals each gets a section of its own (`7f 00 00 00 00 18 00 00 00 90 01 00`), and a `const u8 PStaSub_Unused[8]` global is one section. ## Keeping this list current

After changing a source file, run `compiler_probe.py` on it for both versions, and add, update or remove its rows. A file
gets `complete` in both versions' `delinks.txt` only when all its functions match and its data is written. The report at
`build/b2_us/report.json` helps find candidates, but its fuzzy match can be below 100 for a matching function because of
relocations, and misses some differences, so the probe decides.
